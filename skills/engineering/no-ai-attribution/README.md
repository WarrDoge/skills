# no-ai-attribution

Stops coding agents from crediting themselves in your repositories. Author and committer identity are never touched.

It works in two layers. `SKILL.md` tells the agent not to add attribution. `git-hook` rejects attribution that gets past the agent anyway.

## What is blocked

In commit messages (`commit-msg`):

- `Co-authored-by`, `Assisted-by`, `Generated-by`, or `Co-developed-by` trailers that name an AI (`Claude`, `Claude Opus 5 (1M context)`, `Codex`, `GPT-5`, `gemini-code-assist[bot]`, ...), or that use an `@anthropic.com`, `@openai.com`, or Copilot noreply address
- lines that start with a credit phrase: `Generated with Claude Code`, `🤖 Generated with [Claude Code](...)`, `Generated by ChatGPT`, `Generated by AI`, `Assisted by Claude`
- `AI-assisted` or `AI-generated` on a line of its own, or as a trailer
- `Claude-Session:` trailers and agent session URLs (`claude.ai/code/session_...`, `chatgpt.com/codex/tasks/...`)

In added lines of staged files (`pre-commit`), the same credit phrases are blocked when they start a line or follow a comment marker (`// Generated by Claude`, `x = 1  # written by Codex`, `<!-- Generated with ChatGPT -->`, `- Generated with Claude Code`). A comment that says only `AI-generated` is blocked too.

## What is allowed

Matching is anchored to the start of a line or comment, so technical references pass:

```text
Add Claude API integration
Document GPT inference architecture
Fix LLM model loader
Remove "Generated by AI" badge
Co-authored-by: Jane Doe <jane@example.com>
Co-authored-by: Claude Dupont <claude.dupont@example.com>
client = anthropic.Claude()
# Detect AI-generated images in uploads
```

## How the hooks work

`install.sh` copies `git-hook` to `~/.config/git/hooks/ai-attribution`, symlinks it under every standard hook name, and sets `core.hooksPath`. The script checks the commit for `commit-msg` and `pre-commit`. For every hook name it then runs the repository's own `.git/hooks/<name>` if one exists. That keeps pre-commit framework hooks, `pre-push` hooks, and git-lfs working.

`reference-transaction` and `post-index-change` are not chained. They fire on every ref update or index write, so a repository that relies on them locally stops running them.

A repository with its own `core.hooksPath` (husky, `.githooks`) overrides the global setting, and the checks don't run there. To add them, call the global hook from that repository's hook, e.g. `~/.config/git/hooks/commit-msg "$1"` in `.husky/commit-msg`.

Hook managers also see the global `core.hooksPath`: `pre-commit install` refuses to run, and `lefthook install` writes into `~/.config/git/hooks`. Run them as `GIT_CONFIG_GLOBAL=/dev/null pre-commit install` so they write to `.git/hooks`, where the chain picks them up.

## Install

Hooks, from a clone of this repository:

```sh
sh skills/engineering/no-ai-attribution/install.sh
# sets: git config --global core.hooksPath ~/.config/git/hooks
```

The installer refuses to run if `core.hooksPath` already points somewhere else.

Skill: `npx skills@latest add WarrDoge/skills`, or symlink this directory into `~/.claude/skills`, `~/.codex/skills`, `~/.hermes/skills`, or `~/.opencode/skills`. For an agent without skill support, paste the body of `SKILL.md` into its `AGENTS.md` or rules file.

Agent settings:

- Claude Code: in `~/.claude/settings.json`, set `"attribution": {"commit": "", "pr": "", "sessionUrl": false}`.
- Codex (0.154): attribution is an account-level setting, and there is no local config key for it. The hooks still apply.
- Hermes Agent and OpenCode: no attribution setting.

## Uninstall

```sh
sh skills/engineering/no-ai-attribution/install.sh --uninstall
```

This unsets `core.hooksPath` and removes only the files the installer created.

## Bypass and exemptions

- One commit, repository hooks still run: `ALLOW_AI_ATTRIBUTION=1 git commit ...`
- One commit, all hooks skipped: `git commit --no-verify`
- Paths that legitimately contain these phrases (product copy, docs about AI tooling) can go in `.gitattributes`. The exemption applies to `pre-commit` only:

  ```text
  docs/ai-labels/** -ai-attribution-check
  ```

## Adding patterns

Patterns live at the top of `git-hook` as lowercase POSIX ERE, one per line. Write `[.]`, `[(]`, and `[[]` instead of backslash escapes. Add a case to `test.sh`, run `sh test.sh`, then re-run `install.sh` to copy the new version.

## Limitations

- The matching is a heuristic. Unusual phrasing ("thanks, Claude") passes. Product text that starts a line with a credit phrase ("Generated by OpenAI's embedding model") is blocked, so use the `.gitattributes` exemption for it.
- A human co-author whose name is an AI name followed only by model-like words (`Claude 2`) is blocked.
- PR descriptions and release notes written on GitHub never pass through git. Only the skill and the agent settings cover them.
- Existing history is not checked. Rebase and cherry-pick don't run `commit-msg`, so old attributed commits carry over.
- Concluding a conflicted merge runs `pre-commit` over the incoming changes as well.
- If the hook itself fails (unreadable message file, scan error), it warns and lets the commit through.
